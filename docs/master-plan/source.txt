1. What we are building
One-liner: A computer vision model finds oil and gas well symbols on historical USGS topographic maps, flags the ones missing from state records, and ranks them for plugging crews, who confirm leaks with a cheap handheld methane sensor that logs readings back to a live map.
Problem
Orphaned oil and gas wells leak methane, and some sit near homes and schools. Crews cannot plug wells nobody knows about.
Old topographic maps marked wells decades before modern record-keeping, but nobody can scan them by hand.
Do not quote a national count of undocumented wells without a cited source. Verify funding program status (2021 Infrastructure Act) before pitching.
Why now: Berkeley Lab and partners have shown deep learning can find undocumented wells on historical maps. Our differentiator is the end-to-end workflow: detect, cross-check against records, rank, verify in the field. USGS TopoView maps are free and georeferenced.
Goals
G1: Show the full loop live (detect, cross-check, rank, verify in the field).
G2: Ranked candidate list for one region with a plain-English brief per well.
G3: A sensor reading changes a well's status on the live map in under 5 seconds.
G4: Report detector accuracy honestly, on maps we actually checked.
G5: Use sponsor tools only where they do real work (Convex, Anthropic; Droid and Apify only if they ship).
Non-goals: not a production system, not certified emissions measurement, no claim of verified undocumented wells, one region only, the MQ-4 is a demo-grade indicator with a simple threshold.
Weekend success metrics
3 of 3 rehearsal runs succeed without manual intervention.
Detector precision and recall on held-out tiles: report actuals, aim for 0.60+.
Pixel-to-lat/lon error under 50 m median on at least 10 detections matched to known CalGEM wells.
Reading reaches Convex in under 2 s, and the map updates in under 5 s end to end.
Submitted with margin.
2. Users and demo story
Program analyst (primary): state orphan well program staffer who needs a defensible ranked list with reasons.
Field verifier (secondary): crew member who walks to a candidate and gets a quick yes/no on a leak.
Community or health reviewer (tertiary): wants to see which candidates are near homes and schools.
Judges see both views.
Story judges should leave with: old map symbols light up as candidates, the presenter picks the top-ranked one, "walks" to it with the handheld near a simulated leak, the reading appears live, the well turns red and jumps to the top, and a Claude-written brief explains why it matters.

5. Architecture and data contracts
Flow: USGS maps → tile → YOLO detect → pixel-to-lat/lon → dedupe → CalGEM match → OSM enrich → score → Convex → Command Map and Field View. Handheld → phone-tagged readings → Convex → both screens, live.
Stack: Python (GeoPandas, rasterio, pyproj), YOLO + Roboflow, Convex (live store and HTTP endpoint), Next.js + MapLibre, Claude via Anthropic API, ESP32 + MQ-4 + OLED.
Convex tables: candidates, documentedWells, readings, fieldChecks, statusEvents, briefs, tiles, detections (plus agentRuns and agentSteps only if Droid ships).
Candidate record (pipeline → Convex → app). Agreed fields: id, lat, lon, score, scoreParts {confidence, undocumented, people, water, field}, editionsSeen, nearestDocumentedId, nearestDocumentedDistM, distToHomeM, distToSchoolM, distToWaterM, buildingsNear250m, status, brief, evidenceImages [{year, url}], quadName, detectionId, source (model | ground_truth)
Reading record (sensor → Convex): deviceId, value (relative, baseline-corrected), raw, timestamp, candidateId (attached by phone), lat, lon, locationSource (candidate | phone), isReplay
Status values: candidate, queued, confirmed_leaking, confirmed_not_leaking, no_well, mislocated
Geospatial rules
Distances are computed in a meter-based projection (California Albers, EPSG:3310). Store WGS84 lat/lon for display.
Each tile uses its own transform. Never reuse one sheet's transform for another.
Record each tile's map year and report detector results per era.
Config values, not buried constants: cross-check radius (100 m), dedup distance (20 m), proximity radius (250 m), score weights, elevated/high thresholds, detector confidence threshold (start ~0.4, tune on the held-out set).
Transparent weighted score from scoreParts; weights are placeholders until tuned Saturday. A confirmed leak ranks above all unconfirmed candidates.
6. Requirements and acceptance tests
Ingestion and detector (Emir)
Tile each sheet into 1024 px tiles with ~20% overlap, keeping each tile's ID, sheet, year and transform. Corner coordinates must match the sheet within 1 pixel.
Label in Roboflow across clean, stained, dense and sparse maps and multiple editions. Include negative tiles with lookalikes (survey marks, small buildings, dots in text).
Hold out the test set before training and never train on it. Record the split in a manifest.
Fine-tune YOLO from pretrained weights; commit the run config.
Inference output per detection: box, confidence, class, tile ID, map year, and a small symbol crop.
Pixel-to-geo: unit test with at least 3 control points. Spot-check 10+ detections against CalGEM and report median offset (target under 50 m).
Report precision, recall and example errors on held-out tiles only, stating which maps were checked.
Fallback flag: switch the pipeline between model detections and hand-labeled ground truth.
Records, scoring, briefs (Ryann)
Load CalGEM Kern data; drop missing coordinates, standardize projection, log bad rows. Wells with low-precision location are flagged "uncertain" and excluded from matching, with a count.
Matching: nearest documented well and distance for each detection; no record within 100 m flags a candidate.
Enrichment: nearest home, school and waterway distances and building count within 250 m from OpenStreetMap.
Dedup across overlapping tiles and editions; count editions each well appears in.
Briefs: 80–120 words, four parts (summary, why it ranks here, what's uncertain, next step). Generated only from the candidate's JSON, with no numbers absent from it. Unconfirmed candidates never use the word "confirmed". Cache in Convex and regenerate only when fields change.
Convex mutations for status changes (each logs a statusEvent) and for attaching readings. Priority-weight recompute from stored score parts.
Dropped false detections are marked as such, never silently deleted.
Command Map (Kunjal)
Full-screen MapLibre map of Kern with satellite basemap, historical overlay toggle with opacity slider (under 1 s), map on right, ranked list left, detail panel slides in (under 500 ms).
Candidates as colored dots by score; documented wells as small gray dots; status colors (red leaking, gray no well, etc.) with legend.
Detail panel: evidence images from every edition, score breakdown bars, nearest documented well and distance, brief, status buttons, readings chart.
Everything live from Convex: a status change shows in a second browser window within 1 s, and rank changes animate.
Visible "simulated sensor data" banner whenever demo mode is on.
Field View, mobile web (Kunjal)
Today's list (queued candidates sorted by distance from phone), on-site screen (old map crop, satellite view, distance to predicted spot), Start reading button, live readings chart, log finding form (outcome, photo, note).
Pairing: the phone sends its location and selected candidate to Convex; new device readings attach to that candidate. A logged finding updates the Command Map live.
Handheld (Murad)
Wire the MQ-4 through a voltage divider (its output can reach 5 V; ESP32 inputs tolerate 3.3 V). Use an ADC1 pin, because ADC2 conflicts with Wi-Fi.
On startup average ~30 s of clean air for a baseline; report the rise above baseline. Let the sensor warm up and leave it powered once wired.
OLED shows relative reading, CLEAN / ELEVATED / HIGH, Wi-Fi status and a visible error state. Auto-reconnect to Wi-Fi.
Button toggles reading mode; post one reading per second to Ryann's endpoint (HTTPS, insecure client setting is fine for the demo; note it in the README). Run on the phone hotspot.
20 back-to-back test cycles with the leak source to set realistic ELEVATED and HIGH thresholds. Record a full set of real readings to a file for the fallback.
Battery runs the unit for 30+ minutes. Spare ESP32 with firmware flashed; second unit if parts allow.
Leak source: ask organizers whether an unlit lighter near a mock wellhead is allowed. Get approval in writing. If not, use recorded readings for the leak moment. Always label it simulated.

11. Risks and fallbacks
Labeling too slow or symbols vary by era: split labeling across people, keep the region small. Fallback: ground-truth flag.
Low precision: one era first, tune threshold, show only well-performing sheets, report honestly.
Wrong pixel-to-geo: control points early, demo on tiles already verified against CalGEM.
MQ-4 unstable: power on early, average readings, baseline-correct. Fallback: replay recorded trace, spare sensor.
ESP32 voltage: divider and ADC1 pin. Fallback: spare board.
Venue Wi-Fi blocks the ESP32: use phone hotspot or travel router, test early. Fallback: replay or local network.
No GPS indoors: phone location via the web page, or pin readings to the selected well.
Leak setup unsafe or not approved: ask organizers, label simulated. Fallback: recorded readings and a software "simulate leak" button posting the same reading.
Sponsor integration slips: drop the claim and keep the feature as a script.
Live API or tile outage: cached briefs and demo tiles, backup video.
Scope creep: the must-have list is the product; scope freeze Sat 6 PM; feature freeze Sat 9 PM.
One config flag for live detector vs. ground truth, and live sensor vs. replay.
